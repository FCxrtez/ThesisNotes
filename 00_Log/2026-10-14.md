Todos estos casos estan dados por patrones similares, una mantisa de `'0` y nuestro sumador comete un error al estimar el exponente. Pero sin embargo eran vectores que estabamos generando como vectores de `transition - normal to subnormal` cuando ninguno de los resultados era un numero subnormal. Ahora que generamos estos vectores correctamente tenemos que el sumador produce el resultado correcto, es decir que la logica de calculo de exponente cuando el resultado es subnormal es correcta. El nuevo codigo para generar los vectores es:

```python
    c1, c2, c3 = rng.uniform(1.2, 4.0, size = 3)
    signs      = rng.integers(0, 2, size=3, dtype=np.uint16)

    values     = np.array([c * norm_to_subn_limit for c in [c1, c2, c3]], dtype=np.float16).view(np.uint16)
    signed_v   = (values & 0x7FFF) | (signs << 15)

    signed_v_f16 = signed_v.view(np.float16)
    c_target     = np.float16(rng.uniform(-norm_to_subn_limit, norm_to_subn_limit))

    v4               = c_target - np.sum(signed_v_f16, dtype=np.float16)
    float16_operands = np.append(signed_v_f16, v4)

    return float16_operands.view(np.uint16)
```

## Entonces

- No introducimos ningun cambio a la estructura del sumador, salvo de restar `actual_lzcounter - 1` y luego multiplexar el resultado si el `normalized_mantissa[INTERNAL_PRECISION] == 0`. Esto se cumple siempre, pero servia para evitar flushear el leading 1 en los casos de bug que mencionamos. A pesar de salvar ese flusheo el exponente sigue calculandose mal y la etapa de redondeo modifica el signo y devuelve un resultado incorrecto.

- Sabemos entonces que el sumador sigue teniendo este bug, que curiosamente no se genera en ningun caso, ni en el uniforme, por lo que podriamos tambien concluir que es un caso *interesante*, o caso borde, porque a pesar de todo el sumador ahora esta en el 100%
- Deberiamos llevar esta manera de generar el vector a la branch main, a partir de ese nuevo estado podemos partir el analisis de **control logic vs hardware precision**, ya que solo deberiamos tener entonces un mismatch en los casos de `catastrophic cancellation` y algunos casos de `align stress`.
